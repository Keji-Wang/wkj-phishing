# 题目维护指南

全部题目在 `index.html` 的 `EMAILS` 数组中，一封邮件一个对象。改完保存、刷新页面即生效，无需构建步骤。

## 完整对象结构

```javascript
{
  id: 'e001',
  scenario: 'urgency',          // 场景 key，对应 SCENARIOS 中的定义
  difficulty: 3,                // 难度 1-5，"开始全部训练"按它排序
  title: '紧急密码重置通知',      // 题目名（仅内部标识，学员看不到）
  fromRiskId: 'e001-rX',        // 可选：把发件人地址设为可点击风险点
  email: {
    subject: '...',
    from: { name: '显示名', email: 'sender@example.net' },
    to: 'victim@example.com',
    date: '2026年5月28日 16:32',
    body: `<p>正文 HTML。<span class="risk-point" data-risk-id="e001-r1">可疑文字</span></p>`,
    attachments: []             // 可选：[{ name: 'xx.pdf', size: '245KB' }]
  },
  riskPoints: [
    {
      id: 'e001-r1',            // 与正文 data-risk-id 对应
      type: 'evidence',         // 'evidence' 硬证据 | 'tactic' 话术手法
      label: '风险点标签',        // 提交后解读卡的标题
      severity: 'high',         // low | medium | high | critical（影响分值）
      explanation: '为什么危险',
      correctAction: '正确做法'
    }
  ],
  nextSteps: ['处置建议一', '处置建议二']   // 可选：结果页"下一步怎么做"
}
```

## 正文标注语法

- 可点击文字：`<span class="risk-point" data-risk-id="...">文字</span>`
- 可点击按钮：`<a class="email-cta risk-point" data-risk-id="..." href="#">按钮文字</a>`
- 发件人地址设为可点：在邮件对象上加 `fromRiskId: '该题某风险点id'`（不需要在正文里写 span）
- `href` 一律写 `#`：所有链接只做展示，不允许真实跳转

## 字段参考

**severity 与分值**（提交时命中加对应分，误点固定 -1）：

| severity | 含义 | 分值 |
|---|---|---|
| low | 仅供警惕的弱信号 | +1 |
| medium | 常见可疑特征 | +2 |
| high | 明显危险信号 | +3 |
| critical | 可直接定性的一锤定音证据 | +4 |

**type 两类信号**（解读卡上的标签色）：

| type | 标签 | 判断标准 |
|---|---|---|
| evidence | 硬证据（蓝） | 可以客观核实的事实：域名拼写、收款账号、索要验证码等 |
| tactic | 话术手法（橙） | 心理操控信号：紧迫时限、保密要求、权威包装、损失威胁等 |

一道题两类都建议有；单一表象拿不准时优先归 tactic，避免把话术当实锤。

## 校验要点

1. `riskPoints` 里每个 `id` 必须在正文（或 `fromRiskId`）中有对应的 `data-risk-id`，否则该点无法被选中，永远算漏选；
2. 反过来，正文里的 `data-risk-id` 必须在 `riskPoints` 中有定义，否则点击后不计分且结果页会误标；
3. `id` 全局唯一，建议按 `e007`、`e008` 顺序往下取；
4. 免责与安全底线：全部使用虚构组织、人物与示例域名，正文里不出现真实可跳转链接。

## 新增场景

在 `SCENARIOS` 对象中补充一个 key（名称、图标、描述），首页即出现新场景卡：

```javascript
hr: { name: '内部通知型', icon: '🏢', desc: '仿冒人事、行政等内部部门通知' }
```

## 最小可运行示例（已实测）

往 `EMAILS` 数组末尾追加下面这个对象，刷新页面：首页「紧急施压型」卡片计数 +1，进入后可标记、提交、看解读。此示例于 2026-09-29 实际添加验证通过后移除。

```javascript
{
  id: 'e101',
  scenario: 'urgency',
  difficulty: 1,
  title: '假期补贴登记（示例题）',
  email: {
    subject: '【人事部】假期补贴登记今日 18:00 截止',
    from: { name: '人事部', email: 'hr-notice@company-hr.net' },
    to: 'chen@company.com',
    date: '2026年6月1日 10:00',
    body: `<p>各位同事：</p>
<p><span class="risk-point" data-risk-id="e101-r1">补贴登记今日 18:00 截止，逾期不再受理</span>，请立即点击 <a class="email-cta risk-point" data-risk-id="e101-r2" href="#">登记领取</a>。</p>`,
    attachments: []
  },
  riskPoints: [
    { id: 'e101-r1', type: 'tactic', label: '当日截止的人为时限', severity: 'medium',
      explanation: '以"今日截止、逾期不受理"制造紧迫感，压缩核实时间。',
      correctAction: '通过公司 OA 或当面问 HR，核实是否真有此通知。' },
    { id: 'e101-r2', type: 'evidence', label: '仿冒 HR 邮箱域名', severity: 'high',
      explanation: '发件域名 company-hr.net 不是公司官方域名，仿冒内部部门是常见手法。',
      correctAction: '核对发件域名；内部通知以 OA/企业邮箱为准。' }
  ],
  nextSteps: ['把邮件原文转发给 IT 安全部门备案。']
}
```

## 改完怎么验证

1. 本地起服务：`python -m http.server 8000`，浏览器打开 `http://localhost:8000`；
2. 首页对应场景卡片「N 道题目」计数 +1；
3. 进入新题：两个风险点都能选中/取消，提交后解读与"下一步怎么做"完整显示；
4. 控制台无报错。
